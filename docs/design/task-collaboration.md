# Task collaboration workspace

## Product contract

Implement the approved UI Lab P0/P1 loop: new Work draft first send confirmation → runtime questions → read-only AI plan → real results → optional next prompts. Chat/Work history classification remains unchanged. Chat sends directly. No extra inference request generates questions or next prompts; new model calls are not authorized for acceptance.

## Owners and event order

```text
composer draft (text + taskStart fields; attachments transient)
  → first Work send opens local confirmation (no model dispatch)
  → confirm once → existing submission + commandId → CommandInbox / runtime
  → pendingInteractions → selected-session question dialog → resolveInteraction
  → successful TodoWrite → sessionStore → product projection snapshot.plan → read-only progress
  → completed assistant text → next-prompt parser → empty composer preview
  → explicit accept, same scope/revision, still empty → existing editor replace → user sends
```

- The current draft owner persists startup outcome/deliverable/constraints alongside text. Cancel/Escape returns without dispatch or losing edits; new session/draft first send only. Ordinary sends, queue, retries, and existing sessions do not reopen intake. Confirmation adds notes to the same original input and submission; preserves attachment/context identity. Prewarm may create an empty runtime but must not execute a model before confirmation.
- `pendingInteractions` remains authoritative. Only focused session auto-opens each ordinary question once. Defer/Escape collapses without decline; submit sends actual partial answers; explicit skip sends empty answers. Plan approval and tool permission remain separate. Submit lock/error are keyed by workspace identity/session/request. Existing pause-on-interaction remains supported. Plain text Enter inserts newline; choice Enter advances, final choice Enter focuses submit; Cmd/Ctrl+Enter submits; IME never submits. Optional preview is rendered safely.
- Ordinary question auto-resolution defaults off; existing UI Lab setting is also turned off using its supported setting path. Other runtimes/configs remain unchanged. Explicit opt-in remains available.
- Todo authoritative plan changes only after a successful tool result (output or successful input fallback), not scheduled input. A valid empty collection clears plan; malformed data leaves prior fact. Failure/cancel retains previous successful plan. Duplicate labels render distinctly without requiring new durable Todo IDs. Desktop continuous and Web replayable consume the same successful facts and cold replay rules.
- Progress is derived from plan, control and interactions: completed/total and current item; no estimated percentage/time, no manual status writes. Completed steps do not mean test verification. No plan yields actual run state without invented tasks. Chat does not mount the engineering progress summary; its existing generation, stop, error and pending-interaction feedback remains independent. Work keeps its progress summary and expansion controls. Remove the fixed acceptance/unverified label: there is no structured acceptance verdict feeding this component. Completed execution is labeled "本次执行已结束" / "Execution ended", not acceptance passed. Existing results/file changes are reused.
- Assistant final text may carry up to three `::next-prompt{label="..." prompt="..."}` directives. They are suggestions only, never auto-run actions. Runtime/Agent instructions request them within the current model turn, and multi-step Work uses existing TodoWrite; no second generation call. Ignore code/quote/list examples, including Markdown lazy blockquote/list continuations, loose list paragraphs and nested examples. Protect complete root Markdown containers according to the existing lexer; a blank line alone does not end an indented loose list. Classify examples by the directive opening position. Omit already accepted metadata from an analysis-only Markdown projection so quoted parameter syntax cannot reclassify subsequent adjacent metadata; map each normalized UTF-16 character back to its original start/end. Keep the transcript unchanged. Streaming scans the original text while excluding all complete directive spans, including malformed metadata that remains ordinary prose, so nested partial protocol in their parameters cannot hide later prose. Markdown syntax inside quoted label/prompt values does not turn top-level metadata into an example. Metadata outside the list (including after a blank line with insufficient continuation indentation, or after a heading/fence boundary) remains extractable. Normalize CRLF/CR only for lexer position mapping, keep UTF-16 original-text boundaries and consume root raw tokens sequentially (only the final block may differ by trailing whitespace); never locate normalized raw by searching later identical text; protect incomplete streaming prefixes and preserve normal copy/share text. Malformed metadata must not crash or cause inference retry. No directives is a valid outcome.
- Suggestion preview belongs only to latest normally completed turn, not error/interrupted/stale turns. Accept requires same workspace/session, unchanged draft version and empty text at actual application; newer input cancels acceptance. Nonempty drafts only preview/copy. IME, active completion menus and read-only/unfocused panes must not consume Tab. UI preferences control startup confirmation and suggestion display; legacy settings default on.
- `followupSuggestionsEnabled` is persisted only by the current Environment's `settingService`. A successful `update` precedes `platform.syncAppSettings`; Desktop Main then sends one `SettingsChanged` invalidation per application window for a strict boolean suggestion preference, reusing the existing shortcut-settings notification. Mixed shortcut/suggestion patches rebuild the menu only for shortcuts and notify each window once. Failed writes never notify. Each window re-reads its own Local/Remote service; notification refresh never writes or rebroadcasts. Settings stores stay service-scoped. If invalidation arrives during an in-flight read, discard that obsolete read and perform a queued latest read before settling; a later notification during that read requests another latest read. Do not use delays to avoid the race. This is Desktop window-local service invalidation, not new cross-device preference synchronization. Existing completed-turn suggestions, draft/IME/Tab guards and restart persistence use the same preference; disabling neither edits transcript nor starts inference.

```text
window A → own settingService.update (durable success)
         → platform.syncAppSettings → Main SettingsChanged → A/B window own service.get
                                                       → service-scoped snapshot only
in-flight get + SettingsChanged → invalidate result → next get → latest snapshot (no write/broadcast)
```

- Timeline/grouped archive and archived-list/Web remote unarchive failures use the existing localized error feedback. Keep the item in its original list, release the pending lock for retry, and handle the rejected promise. A failed RPC is never a successful archive.
- Attention uses existing indexed/snapshot facts from opened workspaces: questions, approvals, errors; select navigates to exact source identity before opening the interaction. No second task database.
- History claim storage failure must be visible and retain an in-memory classification so the newly created session stays findable for this runtime. Explicit local-only storage boundary is shown. Fork/selection-side commands add query-only pending records (original commandId, parent, classification), never replay mutation. ACK/query resolves child identity; unknown remains visible pending confirmation with refresh-history action, without auto-fork.
